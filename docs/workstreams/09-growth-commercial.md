# 09 — Developer Growth & Commercial

## Role
Developer relations / product marketing / commercial lead.

## Mission
Turn real technical value into adoption, feedback, and eventually revenue without compromising evidence quality or turning the project into thin content/marketing claims.

## Owns
- developer documentation/examples
- launch strategy
- open-source adoption
- GitHub/registry presence
- SEO/AEO/LLM discoverability
- community/customer discovery
- pricing hypotheses
- conversion path from free CLI to paid hosted/continuous/proxy features
- partnerships/integrations

## Initial audience
MCP server developers and small AI platform teams supporting multiple hosts.

## Free-to-paid ladder hypothesis
Free/open:
- local CLI
- host rule packs
- basic compatibility report
- CI gate

Paid later:
- scheduled continuous compatibility monitoring
- private/authenticated scans
- historical matrix and regression alerts
- team/project views
- richer live-host validation
- repair intelligence at scale
- hosted compatibility proxy/runtime normalization
- enterprise policy/audit features

## Initial backlog
1. Build competitor/positioning matrix and keep it current.
2. Define 3-5 concrete developer personas/jobs-to-be-done.
3. Create public examples only after Alpha produces real evidence.
4. Prepare README value proposition around multi-host readiness, not generic inspection.
5. Track common compatibility questions/issues from community sources.
6. Define launch channels: GitHub, MCP community/registry, relevant developer communities.
7. Run customer discovery before setting final paid packaging.
8. Develop contribution model for community host-rule updates while preserving source/version quality.

## Marketing constraints
- Never claim security certification.
- Never claim universal compatibility from static checks alone.
- Never publish a server's negative result without clear version/timestamp/evidence context.
- Avoid fear-based messaging about MCP.

## Exit gate for Launch Alpha
A developer can understand in under a minute what MCP Doctor does that Inspector/Conformance/MCPJam do not, run it, and file a useful compatibility case.

## Cross-workstream dependencies
All claims depend on evidence from 01/02/03/05/07. Command Center approves pricing and public positioning changes.
