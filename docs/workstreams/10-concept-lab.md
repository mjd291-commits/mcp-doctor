# 10 — Concept Lab

## Role
Exploratory research / product strategy lab.

## Mission
Investigate ideas deeply before they affect the active product. Protect the build from scope creep while still giving unconventional opportunities a place to mature.

## Owns
- exploratory product ideas
- competitor/market experiments
- protocol/host opportunities that are not yet committed
- feasibility analysis
- second-order effects
- promotion packages for ideas worth moving into production

## Rules
- No production changes directly from Concept Lab.
- Label assumptions versus evidence.
- Check current repo architecture and market before proposing something as new.
- Explicitly test whether an idea duplicates official MCP tooling or a mature competitor.
- Prefer ideas that strengthen compatibility evidence/repair moat.

## Promotion package
A concept may be promoted only with:
1. problem/user,
2. evidence the problem exists,
3. current alternatives/competitors,
4. proposed differentiated solution,
5. technical fit,
6. dependencies,
7. risks/security implications,
8. estimated build effort,
9. monetization/adoption hypothesis,
10. recommended owning workstream.

## Current concept backlog
- vendor-neutral real-host test adapters,
- community compatibility-rule contribution network,
- compatibility badge with cryptographically verifiable evidence bundle,
- repair-rule marketplace/library,
- private self-hosted enterprise scanner worker,
- .NET-native companion implementation only if demand justifies it,
- functional-scenario-linked load testing,
- compatibility change alerts driven by host documentation diffs.

## Cross-workstream dependencies
Concept Lab reads all project docs but writes production recommendations back to Command Center for approval/assignment.
